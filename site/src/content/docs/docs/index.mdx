devtwin is a local command-line tool that keeps what you know about a project, and how you like to work, in one private place on your machine. It then hands that context to whichever coding agent you open next.

The idea is to clone the developer, not just the repository. A repository tells an agent what the code is. It rarely says why a decision was made, what is still unknown, or where the last session stopped. devtwin keeps that knowledge between sessions and between agents.

## Your first brief in five minutes

You need Git and Node.js 22.13 or later. Install devtwin and run the offline demo:

```sh
npm i -g devtwin
devtwin demo
```

Then follow the [Quickstart](/docs/getting-started/quickstart/). It builds a throwaway repository in a temporary folder, onboards it and prints its brief: the short, source-linked summary you give an agent at the start of a session. If you just want to see the result, its [fast path](/docs/getting-started/quickstart/#fast-path) does everything in one paste.

## How you use it

1. **Onboard** a repository. devtwin reads a few files, such as the README and package manifest, and shows you what it would record. You approve that exact plan.
2. **Start a session.** The devtwin hook gives the agent a short summary of the project's key rules and the last handoff. The bundled `devtwin-resume` skill fetches the full brief.
3. **Work.** Agents record decisions, lessons, locations and handoffs as they go, and a daily job imports Claude memory and `docs/solutions`. These project writes need no prompt.
4. **Check the week.** `activity` lists what devtwin did, and `undo` reverses one write. A lesson for every project or a preference waits for your weekly `activity review`. Sending to your team needs a one-time consent.
5. **Export a handoff** when you want to pass selected records to someone else.

See [How it works](/docs/concepts/how-it-works/) for the full picture and the three tiers.

## Your data stays on your disk

The kit you install is public code: the CLI, schemas, skills and generic templates. Everything you add, such as project records, your profile and drafts, lives in separate private folders outside the kit, with private file modes. Nothing is synchronized from your private store into the public kit, and nothing is sent to a hosted service. If you join an organization hub, a Git repository your organization hosts, only the lessons sent under your consent and short "working on" notes go to it.

Onboarding never writes into the project repositories it reads. What devtwin learns goes into your private store. A lesson reaches a repository only under your `repo-push` consent, as a commit on a new `devtwin/learning-<id>` branch.

:::note[Before you start]
devtwin installs from npm with `npm i -g devtwin`. It needs Node.js 22.13 or later, and macOS is the reference platform. [Limitations](/docs/security/limitations/) lists what it does not do yet.
:::
