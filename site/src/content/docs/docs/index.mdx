Developer Context Kit, or `devctx`, is a local command-line tool that keeps what you know about a project, and how you like to work, in one private place on your machine. It then hands that context to whichever coding agent you open next.

The idea is to clone the developer, not just the repository. A repository tells an agent what the code is. It rarely says why a decision was made, what is still unknown, or where the last session stopped. `devctx` keeps that knowledge between sessions and between agents.

## Your data stays on your disk

The kit you clone is public code: the CLI, schemas, generic templates and tests. Everything you add, such as project records, your profile and drafts, lives in separate private folders outside that clone, at file mode `0600`. Nothing is synchronized from your private store into the public kit, and nothing is sent to a hosted service.

`devctx` also never writes into the project repositories it reads. Onboarding reads a few files, such as the README and package manifest, and stores what it learns in your private store.

## How you use it

1. **Onboard** a repository. `devctx` previews what it found; you approve the exact plan.
2. **Read a brief** at the start of a session and give it to your agent.
3. **Record** decisions and findings as you work, so the next session has them.
4. **Export a handoff** when you want to pass selected records to someone else.

Every write is previewed first and applied only when you ask. See [How it works](/docs/concepts/how-it-works/) for the full picture.

:::caution[Experimental]
`devctx` is an early, experimental release. It is not published to npm yet: you run it from a Git checkout with `node bin/devctx.mjs`. It requires Node.js 22.13 or later and is developed and tested on macOS. Read the [limitations](/docs/security/limitations/) before you put real client data in it.
:::
