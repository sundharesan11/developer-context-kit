# Cross-agent context and memory for coding agents: landscape (research date 2026-10-16)

Scope: public web research only. No local code or private file contents were sent to any web tool.
Confidence markers: **[official]** = vendor docs/changelog fetched or quoted; **[secondary]** = third-party blog/directory; **[unverified]** = could not confirm against a primary source.

---

## 1. Instruction-file standards and built-in agent memory

### AGENTS.md (agents.md)
- **What:** plain Markdown, no schema, "a README for agents". Nested files supported; "the closest AGENTS.md to the edited file wins; explicit user chat prompts override everything." OpenAI's main repo had 88 nested files when the page was written. [official] https://agents.md/
- **Adopters listed on agents.md:** Codex, Jules, Gemini CLI, Devin, Windsurf, Junie, UiPath, Copilot coding agent, Factory, Aider, goose, opencode, Zed, Warp, VS Code, Amp, Cursor, RooCode, Kilo Code, Augment Code and others. [official] https://agents.md/
- **Stewardship:** contributed by OpenAI to the Agentic AI Foundation (AAIF), a Linux Foundation directed fund announced Dec 2025, alongside Anthropic's MCP and Block's goose; supported by Google, Microsoft, AWS, Bloomberg, Cloudflare. Claimed 60,000+ adopting projects. [official] https://openai.com/blog/agentic-ai-foundation, https://infoq.com/news/2025/12/agentic-ai-foundation/
- **Gap:** AGENTS.md is a *repo-committed, team-shared, rules-only* file. It has no standard user-level location (proposals split between `~/.agents/AGENTS.md` and `~/.config/agents/AGENTS.md`; see complaints), no notion of "state/handoff", no provenance, and no freshness metadata.
- **Our tool:** interoperate. Never compete with AGENTS.md as the instruction file; optionally *generate a small fragment* (or a pointer) that agents can read, but keep personal/cross-repo state outside the repo.

### Claude Code (CLAUDE.md hierarchy, auto memory, AGENTS.md)
- **Hierarchy:** managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md` etc.), user `~/.claude/CLAUDE.md`, project `./CLAUDE.md` or `./.claude/CLAUDE.md`, `CLAUDE.local.md`, plus `.claude/rules/*.md` (optionally path-scoped via `paths` frontmatter) and user-level `~/.claude/rules/`. Docs advise <200 lines per CLAUDE.md; imports "don't reduce its context cost". [official] https://code.claude.com/docs/en/memory
- **Imports:** `@path` imports, relative or absolute, recursive to 4 hops. Imports resolving outside the working directory trigger a one-time **approval dialog** in project files; user-scope files are trusted. Docs explicitly suggest `@~/.claude/my-project-instructions.md` to share personal per-project instructions across worktrees. [official] same URL
- **AGENTS.md:** since v2.1.277 Claude Code reads AGENTS.md *only when no CLAUDE.md/CLAUDE.local.md exists* (default `claude-md-or-agents-md`); a `claude-md-and-agents-md` setting loads both. `~/.claude/CLAUDE.md` does not count for that check. [official] same URL. The long-running request was anthropics/claude-code#6235 (reportedly closed Aug 2026). [secondary] https://thepromptshelf.dev/blog/claude-code-6235-agents-md-closed-completed-2026/
- **Auto memory:** Claude writes typed notes (`user`, `feedback`, `project`, `reference`) to `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index; first 200 lines/25KB of the index load each session, topic files on demand. **Machine-local**, shared across worktrees of a repo, not synced across machines; not swept by transcript retention. On by default; `autoMemoryEnabled`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `autoMemoryDirectory` to relocate. Writes are *not* previewed/approved per item. [official] same URL
- **Memory tool (API):** `memory_20250818`, client-side; the app executes CRUD against its own `/memories` store. [official, via search excerpt] https://platform.claude.com/docs/es/agents-and-tools/tool-use/memory-tool
- **Output styles:** exist as user/project-level system-prompt modifiers and are audited alongside memory files (`/doctor prompt-audit`). [official, mention only] https://code.claude.com/docs/en/memory
- **Gap:** auto memory is per-repo, per-machine, Claude-only, unapproved, and unsourced. CLAUDE.md is instructions, not state.
- **Our tool:** interoperate. The cleanest bridge is a user-level or `CLAUDE.local.md` `@import` of a dck-generated file (Claude already shows an approval dialog for external imports). Do not replicate auto memory; optionally offer *import of* auto-memory entries into reviewed dck facts.

### OpenAI Codex CLI
- **AGENTS.md:** global `~/.codex/AGENTS.md` (or `AGENTS.override.md`), then project-root-to-cwd walk, one file per directory, concatenated; 32 KiB `project_doc_max_bytes` cap; `project_doc_fallback_filenames` config. [official] https://learn.chatgpt.com/docs/agent-configuration/agents-md
- **Memories:** off by default (`[features] memories = true`). Background job summarises idle eligible chats into `~/.codex/memories/` ("treat these files as generated state"); secrets redacted from generated fields; per-chat `/memories` opt-out; delete option. Docs: memories are "a recall aid, not a rulebook... keep required team guidance in AGENTS.md". [official] https://learn.chatgpt.com/docs/customization/memories?surface=app
- **Gap:** Codex-only, machine-local, auto-generated without per-item approval, no source links.
- **Our tool:** interoperate via `~/.codex/AGENTS.md` (or fallback filename) pointer; never write into `~/.codex/memories/`.

### Cursor
- **Rules:** project `.cursor/rules/*.mdc`; User Rules (Customize > Rules, all projects, storage location not documented); Team Rules from dashboard with precedence Team > Project > User; AGENTS.md incl. nested. [official] https://cursor.com/docs/context/rules
- **Memories:** launched ~1.0 (June 2025), **removed in 2.1.x**; staff told users to "Export memories" to `.mdc` rules; reports of memories still applied without UI and of hidden old user rules still applying. [secondary/forum] https://forum.cursor.com/t/are-my-memories-gone/144057, https://forum.cursor.com/t/memories-not-showing/143820, https://forum.cursor.com/t/possible-bug-old-user-rules-from-old-cursor-still-existing-but-not-showing-up-in-the-ui/149060
- **Global AGENTS.md:** requested, not supported. [forum] https://forum.cursor.com/t/support-global-agents-md/150406
- **Gap/lesson:** a vendor dropped auto-memory in favour of explicit rule files. User Rules are not file-based, so we cannot write to them; Cursor reads project AGENTS.md.

### Windsurf (Cascade)
- Auto-generated memories stored locally in `~/.codeium/windsurf/memories/`, scoped to the workspace, not carried across workspaces, not in the repo. Global rules file capped at 6,000 chars. Windsurf itself recommends putting reliably reusable knowledge in Rules or AGENTS.md. [official] https://docs.windsurf.com/windsurf/cascade/memories.md

### Cline Memory Bank
- A **methodology, not a feature**: six Markdown files (`projectbrief.md`, `productContext.md`, `activeContext.md`, `systemPatterns.md`, `techContext.md`, `progress.md`) in `memory-bank/` inside the repo, driven by a `.clinerules` instruction; updated when the user says "update memory bank". Accuracy depends on maintenance. [official] https://docs.cline.bot/customization/memory-bank
- **Lesson:** the most-copied pattern in the space; `activeContext.md`/`progress.md` are effectively a handoff. It lives in the repo and is agent-maintained without review, which is the gap we target.

### Roo Code
- Global and mode-specific custom instructions; `.roo/rules/`, `~/.roo/rules/`, `.roo/rules-{mode}/`; AGENTS.md support since ~3.24 via `roo-cline.useAgentRules`, root only. [official+secondary] https://docs.roocode.com/features/custom-instructions, https://thepromptshelf.dev/blog/roo-code-agents-md-setup-guide-2026. rulesync lists Roo Code as deprecated/EOL target [official README] https://github.com/dyoshikawa/rulesync

### Kiro (steering)
- Workspace `.kiro/steering/` and global `~/.kiro/steering/`; workspace wins on conflict; teams may push global steering via MDM; `KIRO_HOME` relocates. Global `fileMatch` inclusion bug reported. [official] https://kiro.dev/docs/steering/, https://kiro.dev/docs/configuration/, https://github.com/kirodotdev/Kiro/issues/9176

### GitHub Copilot
- Repo `.github/copilot-instructions.md`, `.github/instructions/**.instructions.md`, AGENTS.md (root + nested), CLAUDE.md, GEMINI.md read by the coding agent. [official] https://github.blog/changelog/2025-08-28-copilot-coding-agent-now-supports-agents-md-custom-instructions ; cheat sheet https://docs.github.com/enterprise-cloud@latest/copilot/reference/customization-cheat-sheet
- Personal instructions path `~/.copilot/copilot-instructions.md` for CLI: [unverified]
- **Copilot Memory:** cloud, repo-scoped, validated against current code before use, auto-expires after 28 days unused; on by default for Pro/Pro+ (Mar 2026); reviewable under repo settings. [official] https://github.blog/changelog/2026-01-15-agentic-memory-for-github-copilot-is-in-public-preview/, https://github.blog/changelog/2026-03-04-copilot-memory-now-on-by-default-for-pro-and-pro-users-in-public-preview/, https://docs.github.com/en/copilot/concepts/agents/copilot-memory
- **Lesson worth copying:** *citation/validation before use + expiry* is GitHub's answer to stale memory. dck's source links can do the same locally (re-check the cited file/commit before surfacing a fact).

Borrow ruler's good UX: dry-run, managed blocks with markers, `.bak` backups, `revert`.

## 4. Session archive / transfer / handoff

- **SpecStory:** IDE extension + CLI wrapper (`specstory run claude|codex|cursor`), `specstory sync` backfills from `~/.claude/projects/*.jsonl` into `.specstory/history/` Markdown; secret redaction; optional cloud sync; `resume` into another installed agent. https://docs.specstory.com/integrations/terminal-coding-agents, https://docs.specstory.com/faqs, https://docs.specstory.com/integrations/terminal-coding-agents/resume
- **continues (npm) / casr (Rust):** read native session formats, convert, inject into a target agent; claims 16 agents; `--preview` of the handoff doc. Formats are "undocumented, proprietary, and incompatible". [secondary] https://codex.danielvaughan.com/2026/06/01/codex-cli-cross-agent-session-portability-continues-casr-handoff/
- **Others:** cct (codex-claude-transfer) https://pkg.go.dev/github.com/ahmojo/codex-claude-transfer ; sess (distils to Markdown brief) https://pypi.org/project/sess/ ; showagent https://glama.ai/mcp/servers/aytzey/showagent ; catchup `fork --into`; many "handoff" skills (cold-start prompt) https://www.skills.sh/pc-style/skills/handoff
- **Built-in `/handoff` in Amp/Codex/Claude Code:** not confirmed by this search. [unverified]
- **Consensus from guides:** hand off compact working state (goal, changed files, decisions, failed attempts, verification state, next action), not transcripts; transcripts carry stale context and dead ends. https://superset.sh/blog/switching-between-ai-coding-agents
- **Verdict:** transcript archive/transfer is covered (SpecStory, continues). dck's handoff should be a *reviewed, compact, source-linked* note, possibly seeded from a transcript tool's output, not a transcript store.

## 5. Public complaints and requirements

1. **Instruction bloat / context rot.** Chroma's "context rot" research: reliability drops as input grows even on simple tasks; distractors hurt. https://trychroma.com/research/context-rot. Practitioner posts: "the more rules you add, the fewer rules the agent follows" https://dev.to/johnonlee/how-to-keep-your-claudemd-light-and-why-more-rules-make-agents-worse-34fa ; https://codex.danielvaughan.com/2026/03/27/agents-md-bloat-problem/ ; Claude docs themselves cap advice at <200 lines https://code.claude.com/docs/en/memory
2. **Context files can hurt.** Gloaguen et al. (ETH Zurich, arXiv 2602.11988): context files tended to reduce task success vs none and raised cost >20%; recommend only non-obvious, specific instructions. https://arxiv.org/abs/2602.11988v1. Counterpoint: Lulla et al. found ~28.6% lower median runtime and ~16.6% fewer output tokens with AGENTS.md. https://arxiv.org/html/2601.20404v2
3. **Stale / wrong / ignored memories.** Claude Code issues: over-reliance on memory causing stale-state errors (#62812) https://claudeissues.com/issue/62812-bug-claude-ignores-claude-md-rules-and-over-relies-on-memory-causing-stale-state ; saved feedback not applied (#37314, #37847, #43393, #42371) https://claudeissues.com/issue/37314-claude-repeatedly-fails-to-apply-its-own-memory-feedback-same-mistakes-recur-acr , https://claudeissues.com/issue/43393-auto-memory-feedback-not-reliably-applied-in-subsequent-conversations (claudeissues.com mirrors GitHub; originals not opened [unverified mirror]). Stale CLAUDE.md "describing a codebase that had moved on" https://tianpan.co/blog/2026/04/13/claude-md-as-codebase-api. Copilot added 28-day expiry precisely "to keep stale information from affecting agent decisions" https://docs.github.com/en/copilot/concepts/agents/copilot-memory
4. **Vendor memory churn / hidden state.** Cursor removed Memories; users lost them or found them still applied without UI; old user rules applied invisibly. https://forum.cursor.com/t/are-my-memories-gone/144057 , https://forum.cursor.com/t/cant-clear-memories/148254 , https://forum.cursor.com/t/possible-bug-old-user-rules-from-old-cursor-still-existing-but-not-showing-up-in-the-ui/149060
5. **Privacy / security.** Memory poisoning of Claude Code memory files (Cisco) https://blogs.cisco.com/ai/identifying-and-remediating-a-persistent-memory-compromise-in-claude-code ; Supermemory recall auto-ran a crafted Bash command https://supermemory.ai/changelog/plugins/claude ; mem0 telemetry opt-out reportedly ineffective https://github.com/mem0ai/mem0/issues/2062 ; NVIDIA NemoClaw added secret scanning on memory writes https://perspectives.nvidia.com/nvidia-nemoclaw/prevent-ai-agent-writing-api-keys-long-term-memory/ ; academic extraction attacks on agent memory https://arxiv.org/html/2502.13172v2 . "Bad Memory" July 2026 paper on Claude Code/Codex file memory [unverified].
6. **Cross-tool fragmentation.** "Every major AI player has slipped a rules or memory file into its workflow" https://aiagentsexplained.substack.com/p/agent-rule-files-yet-another-tower ; no import from Cursor to Claude Code https://usagebar.com/blog/switching-from-cursor-to-claude-code-cli ; session formats proprietary and incompatible (continues/casr write-up above); long-running Claude Code AGENTS.md request #6235 and duplicates #31005/#34235 https://claudeissues.com/issue/34235-feature-request-support-agents-md-as-a-native-context-file-alongside-claude-md
7. **User-level preference portability.** Requests for a shared global `~/.agents/AGENTS.md` in Claude Code https://claudeissues.com/issue/62371-feature-request-support-global-agents-agents-md-along-with-project-level-agents and pi https://github.com/earendil-works/pi/issues/5002 ; Cursor global AGENTS.md https://forum.cursor.com/t/support-global-agents-md/150406 ; current DIY is symlinked dotfiles https://github.com/RamsesKools/agent-config-example . Built-in memories are machine-local (Claude, Codex, Windsurf) so nothing follows you to another machine without a sync story.
8. **Real Reddit / HN threads:** searches returned mostly blogs; few direct Reddit/HN threads surfaced. One HN thread (Graphiti for Cursor) https://hn.svelte.dev/item/43506068 . Community sentiment on Reddit is therefore **[unverified]** in this report.

## 6. Top 5 takeaways for our tool (dck)

1. **Don't build rules-sync or memory retrieval; occupy the gap between them.** Rules fan-out is solved (ruler, rulesync, vibe-rules) and auto-capture memory is crowded (mem0, claude-mem, Supermemory, Letta, built-ins). The unoccupied niche is *human-approved, source-linked, cross-repo, cross-agent working state and decisions*, kept outside repos. Position explicitly as "the reviewed layer" that complements, not replaces, AGENTS.md and vendor memory.
2. **Interoperate through the native entry points, minimally.** Emit one short generated fragment (or a pointer) per project and wire it via: Claude `@import` from `~/.claude/CLAUDE.md` or `CLAUDE.local.md` (Claude already approval-gates external imports), `~/.codex/AGENTS.md` (or a `project_doc_fallback_filenames` entry), and optionally a project AGENTS.md pointer. Use managed marker blocks, dry-run, backups and revert (copy ruler's UX). Recommend ruler/rulesync for broader fan-out rather than reimplementing ~60 targets.
3. **Make staleness a first-class feature, not an afterthought.** The loudest complaints are stale/wrong memories and bloat. Copy GitHub's idea locally: every fact cites a source (file path + commit/line, URL, or session), is re-validated before being surfaced, and ages out or is flagged when the source changes or it goes unused. Enforce a hard size budget for what gets injected into agents (well under 200 lines), since evidence shows extra context can lower success and raise cost.
4. **Handoff = compact reviewed state, optionally seeded from transcripts.** Transcript transfer exists (SpecStory, continues/casr). dck's handoff should be the small structured note guides recommend (goal, decisions, changed files, failed attempts, verification state, next action), drafted from git state and optionally from SpecStory/Claude/Codex session files, then previewed and approved. Consider *importing* (with review) Claude auto-memory, Codex memories, Cline memory-bank files and Cursor exported `.mdc` so users aren't asked to start from zero.
5. **Privacy and integrity are differentiators worth stating loudly.** Competitors send content to model APIs (mem0, Graphiti, claude-mem), sync to cloud (Supermemory, ByteRover, Letta Cloud), or have had injection/telemetry issues. dck's "no LLM call required to store, secret scan on every write, nothing leaves without approval, plain files you can diff" is a real differentiator. Also treat injected context as an attack surface (memory poisoning): only emit approved content, keep provenance, and never auto-execute anything from stored context. Machine portability (user-level preferences following the developer) is an open need that built-ins don't solve; an approved, git-able store outside repos answers it.
