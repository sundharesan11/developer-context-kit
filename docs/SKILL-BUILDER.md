# Private skill-builder tooling

Milestone A supplies a deterministic private workspace and validator. It does not include a conversational builder skill, installation of generated packages, live-model evaluation or export. The bundled installer still contains three skills. `skills/devctx-create-skill/assets/skill-template.md` is a generic starter, not discoverable skill guidance.

All commands require an explicit disposable `--pilot <pilot.json>` fence. Set `--audience personal|company|project`, `--workspace ws_<id>`, and for company/project set `--scope <scope>`; project also needs `--project <scope.project>`. Company scope must exist in the pilot; project must be in its registry. IDs use prefixes `ws_`, `rq_`, `ds_`, `dc_`, `rv_` followed by 8–64 lowercase letters, digits, underscores or hyphens. Each new ID is an exclusive create. There is no mutable current version.

Use these routes in order, adding the same selection flags each time:

1. `skill discover` lists the three bundled skills. `--fixture <directory>` may inspect a synthetic skill under the pilot's inputs root. It does not inspect agent homes or run scripts.
2. `skill workspace-create` creates one private workspace.
3. `skill requirements-record --requirements rq_example01 --input <requirements.json>` stores immutable requirements. JSON must provide `goal`, `success`, `examples` (at least one request), `negativeExample`, `inputs`, `permittedTools`, `forbiddenTools`, `supportedAgents`, `output`, `failure`, `destination` and `unknowns`.
4. `skill design-record --requirements rq_example01 --design ds_example01 --input <design.json>` stores a design bound to that requirements digest. JSON must provide `name`, `description`, `workflow`, `outputs`, `dependencies`, `tests`, `tree` (including `SKILL.md`) and `reuse`.
5. Present the returned full design digest to the user. Record an explicit response using `skill design-approve --design ds_example01 --decision dc_example01 --interaction-ref user:<reference> --response 'Approved sha256:<full digest>'`. This is self-reported interaction evidence, not identity authentication. Changed named requirements or design make the receipt stale.
6. Put candidate files under a directory in the pilot inputs root. `skill draft-create --requirements rq_example01 --design ds_example01 --decision dc_example01 --revision rv_example01 --candidate <directory>` copies them into an immutable private revision. An unapproved design is refused. Run `skill draft-validate --revision rv_example01`, then inspect `skill workspace-show` for IDs and statuses. A correction uses a new revision ID; no command overwrites a revision.

The validator accepts a **strict documented subset** of Agent Skills frontmatter: UTF-8 text with LF or CRLF, opening and closing `---`, exactly `name` and `description` as unquoted one-line scalars, then nonempty Markdown. It rejects BOM, YAML collections, aliases, multiline or quoted scalars, duplicate/unknown keys, and a trailing delimiter. The name matches `^[a-z0-9]+(-[a-z0-9]+)*$`, is at most 64 characters and matches the approved design; description is at most 1024 characters. This subset is not a general YAML parser or full specification validator.

Packages allow `SKILL.md` and regular files under `references/`, `scripts/`, or `assets/` only. Intake rejects symlinks, hard links, nonregular entries, denied names and unsafe paths; limits are 24 files, 131072 bytes per file, 262144 total bytes and four directory levels. Inline Markdown relative links are checked for existing package files. URL and anchor links are ignored; reference-style and HTML links are reported unchecked. Helpers are never executed by these commands, so their behavior remains unverified. Sensitive-content scanning is a tripwire, not clearance. A failed validator records a failed result for that exact revision and validator version; package tampering blocks validation entirely.

Private draft staging that survives an interrupted write requires manual review. Do not remove it automatically or reuse its revision ID. `workspace-show` reports staged revision IDs and damaged revisions without returning requirements, design or package bodies. Live behavior, routing quality, fresh-agent discovery, real-home activation and publication remain untested or unavailable.
